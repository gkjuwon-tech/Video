## P. 프리모템 요약 (건설적 프리모템): Day 90에 이 렌즈 때문에 v3가 실패했다

### P.0 가정과 방법

- **가정.** 오늘은 Day 90이다. 같은 사진 대결(T2)의 🟢 셀은 대부분 이겼다. 그런데 이 렌즈 영역에서 다섯 가지가 무너졌다.
  1. 법무 의견(L2)이 "COMP 결과로 아키텍처를 고른 것은 개발 사용으로 읽힐 수 있다"고 회신했다. Day-90 게이트 수치를 공개 주장에 쓰지 못했다.
  2. D60 대결 릴 v0의 "우주인과 말" 편이 Soul 스틸을 경쟁 API에 넣은 비교였다. 공개 직전에 내렸다.
  3. 공개 벤치(Kaggle)의 인물 사진 한 장에 동의 철회 요청이 왔다. CC BY 4.0으로 배포한 사본은 회수할 수 없었다.
  4. 4K 쇼케이스의 라벨이 "입력에 없던 영역 2%"였다. 실제로는 화면 디테일의 72%가 발명이었다. 비교 광고 검토에서 막혔다.
  5. 세 렌즈의 Soul·법무·SI 숫자가 서로 달라 Day-90 보고서의 예산표가 맞지 않았다.
- **방법.** 원 메모의 모든 주장과 숫자를 v2.1 원문, 자매 렌즈 개정판(카탈로그 F-M1–M14, 파이프라인 F-P1–P13), 벤치 렌즈(§2.2–§2.6, §4.6, §4.8), 약관 원문과 대조했다. 실패 지점마다 무엇이, 왜, 어떤 숫자에서 무너졌는지 적었다. 업그레이드는 목표를 낮추지 않는 설계 변경, 실험, 가드, 폴백 사다리로만 붙였다.
- **결론 한 줄.** 원 메모의 뼈대(ECF, 1-입력 원칙, 개발 방화벽, U0/U1/U2 사다리, 이미지 전용 입구, 주장 장부)는 맞다. 무너진 곳은 **경계가 말로만 있었던 곳**이다. 개발 방화벽이 게이트 자체를 금지했고, 사람이 읽는 보고서가 세탁 통로가 됐고, 발명 라벨이 한 축만 셌고, 벤치 입력의 권리 사슬이 벤더와 크라우드까지 이어지지 않았고, 클린룸이 프로세스 밖(메모리·캐시·Kaggle)에서 샜다.

#### F-R2. 개발 방화벽의 자기모순: COMP가 게이트를 돌린다

- **무엇이.** 원 메모 CT-R3은 COMP를 회귀셋·튜닝·선택 신호에서 뺐다. 그러나 v3 계획의 핵심 루프는 "Day-90 게이트 VP ≥70%, 실패하면 업그레이드"다. 이 루프는 COMP 결과로 돈다. 엄격하게 읽으면 우리는 경쟁 출력으로 우리 서비스를 개선했다.
- **어디가 위험한가.** Gemini API 추가 약관은 서비스와 경쟁하는 모델 개발에 서비스를 쓰는 것을 막는다 [검증]. 우리 비디오 모델은 Veo와 경쟁한다. 다른 벤더 조항은 미확인이다(L7·L8).
- **업그레이드: PnP 규칙 [신규 운용, CT-R9].** 신호를 둘로 나눈다.

| 신호 | 정의 | 예 | 허용 출처 |
|---|---|---|---|
| **J(판정)** | 합격/불합격, 녹/황/적, 우선순위 순서. 사람의 결정 기록으로만 간다 | Day-90 게이트, D60 대결 릴 판정, Failure Twin 우선순위 | 모든 출처(COMP, EXTGEN, TEL-CAGG, EVAL-ONLY 포함) |
| **S(선택)** | 후보 중 argmax, HP 탐색, 손실, 보상, 회귀셋 합격선, 체크포인트·프리셋 선택 | 교사 선정, 아키텍처 arm 선택, 임계값 튜닝 | `dev_ok`인 출처만(ENGINE, CAPTURE, ASSET, SI, OPEN-GEN 학습·dev, TWIN) |

```text
signal_class(x) = 'S' if dev_ok(x) and EVAL_ONLY ∉ x.taint else 'J'
CI: selection_job.inputs 중 signal_class == 'J' 가 하나라도 있으면 실패
PR 템플릿: "무엇을 할지"(J 근거 허용) / "어떻게 골랐는지"(S 근거만) 두 칸
정보 예산: COMP 게이트 조회는 D30·D60·D90 3회. 조회당 녹/황/적 log₂3 ≈ 1.6 bit → 누적 ≤ 4.8 bit
```

- **해석 근거(법무 L18로 확인).** S 선택은 후보 N개에서 log₂N bit를 경쟁 출력에서 끌어온다. 64개 arm 선택이면 6 bit가 한 번에 들어온다. J 판정은 90일 동안 5 bit 이하다. 공개 벤치를 보는 일반 소비자와 같은 수준의 정보다.
- **Veo 처리.** L18 회신 전에는 Veo 결과를 공개 벤치 보고(J)에만 쓴다. 내부 엔지니어링 게이트는 나머지 셋 중 최강으로 판정한다. **Phase 1 공개 승리 주장에는 Veo가 그대로 들어간다**(목표 유지).
- **폴백 사다리.** L18 긍정 → PnP 그대로. L18이 J도 막으면 → 게이트를 절대 지표(GeCo ≤0.03, 왕복 비트 동일, 숨쉬기 지수, MTF50, T0 오라클 대비 VP)로 판정하고 COMP는 공개 보고로만 쓴다. 이때도 공개 승리 목표는 그대로다.

#### F-R3. 사람 세탁 통로: 보고서를 읽은 사람이 분포를 맞춘다

- **무엇이.** 원 메모 §1.11은 "가짜 입력 분포를 실제 입력 분포에 맞추는 신호는 TEL-SYS와 사람이 읽는 TEL-CAGG 보고서뿐"이라고 적었다. 사람이 보고서를 읽고 에셔 교란 크기 q, θ 샘플러 범위, 생성기별 판독 프리셋을 고치면, 사용자·외부 생성기 출력에서 파생된 데이터로 학습 분포를 정한 것이다.
- **어디에 걸리나.** (i) Higgsfield 5.2(iv) "any data derived therefrom" [검증]. (ii) 원 메모 자신의 Q17(INSPIRED 학습 금지). (iii) 우리 약관 문안 "train, fine-tune, **or otherwise improve**". (iv) 카탈로그 Failure Twin이 Esc·PCI·IR·FFD 띠를 TEL-SYS로 분류했다. 이 띠들은 입력 픽셀에서 계산한 값이라 TEL-CAGG다.
- **업그레이드 1: 근거 화이트리스트.** 학습 분포를 정하는 모든 설정(SI 교란 q, θ 샘플러 범위, LUT 기저, 판독 프리셋, 에셔 합성 크기)은 아래 근거만 쓴다.

| 근거 | 예 | 태그 |
|---|---|---|
| 물리 범위 | 렌즈 f/0.95–f/22, 태양 고도 −6°–90°, EV ±4, 그레인 ISO 100–12,800 | `PHYS` |
| 자체 촬영 통계 | I-OWN dev분, 오라클 장면 | `CAPTURE` |

- **업그레이드 3: TEL 재분류.** TEL-SYS = 단계, 오류 코드, 지연, 메모리, 선택한 무브 등급, 내보내기 형식. TEL-CAGG = Esc·PCI·IR·FFD 띠, 입력 부류, 얼굴 범주, 레벨. Failure Twin은 TEL-CAGG를 **J 신호(우선순위)**로만 받는다(PnP).

- **INSPIRED의 실무 정의 [개정].** "본 적 있다"는 INSPIRED가 아니다. **참조 행위**(나란히 놓고 맞춤, 파라미터 전사, 화면 측정)로 만든 산출물만 `EXTGEN-INSPIRED`다. 우리가 쓴 프롬프트 텍스트는 입력이라 출력 제한을 받지 않는다(Higgsfield 4.4: 입력 소유권은 사용자). 그래서 Soul 데모와 같은 프롬프트 목록을 SI 입구 생성에 써도 된다. 다만 Soul 결과를 보고 고친 이력은 기록한다(L2).

- **격차 게이트(J).** D60에 Δ = VP(INT-soul) − VP(PUB-away)를 잰다. Δ < −10%p면 사다리를 한 단 올린다(P2 → P3). 판정만 하고 어떤 프록시를 쓸지는 프록시 자체의 지표로 고른다.
- **폴백 사다리.** P0–P2로 재현 실패 → P3 의뢰(2주) → P4 파트너 계약 협상 의제 → 그 결함 부류는 메뉴에서 등급 상향(🟢 → 🟡) 표기. 목표 수치는 그대로다.

#### F-R5. 1-입력 원칙의 경계: W는 얼마나 커도 되나

- **무엇이.** 원 메모 CT-R2는 "최적화되는 파라미터는 그 입력의 장면 표현(W, θ_in, 조명, 견본)뿐"이라고 했다. 그런데 W 자체가 크다. TSQ/2DGS 장은 densify 상한 0.4M splat(v2.1 E6)이고 splat당 14–58개(위치, 회전, 스케일, 불투명도, 색 SH 차수 0–3) 파라미터라 **6–23M**이다. 2K 입력의 관측값은 2048 × 1152 × 3 ≈ 7.1M개다. 겉으로는 "입력보다 큰 모델을 입력에 학습했다"로 보인다.
- **정직한 계산.** W 파라미터 대부분은 입력이 아니라 교사가 지은 발명 영역에 맞춰진다. 입력 픽셀이 직접 구속하는 몫은 대략 관측 면적 비율(1 − IR_geo의 세계 평균)이다. 풀 무브 세계에서 30% 안팎이다(추정). 그리고 W는 그 장면 말고는 아무것도 만들지 못한다. 일반화 능력이 0이다.
- **업그레이드: W 파라미터 등급표 [신규 운용, CT-R2 개정].**

| 등급 | 무엇 | 예 | 1-입력 원칙 | 조건 |
|---|---|---|---|---|
| **A 명시 장면** | 해석 가능한 장면 값 | STRATA 블록, splat, 텍스처 페이지, 메시, 해석 조명, θ_in, 견본 | U0(추론) | 조건 1–4(§1.3) |
| **B 장면별 신경 표현** | 그 장면 전용 작은 신경장·잠재 코드 | 해시 그리드 + 작은 MLP 텍스처, 장면별 잠재 코드 | U0, 단 조건 추가 | (B1) 파라미터 수 ≤ 그 세계의 관측·발명 샘플 수, (B2) 공유 가중치에서 읽기 전용 초기화 또는 고정 seed, (B3) 다른 세계에 재사용 0, (B4) 삭제 폐포 안 |
| **C 공유 가중치** | 여러 세계가 쓰는 모델 | MRH, TexelFM, G-Adapter, 교사, LoRA, 헤드 | **금지** | 카탈로그 CT-M5(가중치 불변). TTT, 온라인 헤드 학습, 세계별 LoRA 모두 금지 |

- **작업 명세서(L1 질의용).** 법무에 추상 질문을 보내지 않는다. 한 장짜리 명세서를 보낸다: (1) 입력 바이트가 들어가는 연산 목록(판독, 약한 노이즈 교사 통과, 견본 추출, W 피팅), (2) 연산마다 갱신되는 파라미터의 등급(A/B/C), (3) 결과물의 수명과 재사용 범위, (4) 삭제 방법, (5) "이 파라미터로 다른 이미지를 만들 수 있는가"에 대한 답(아니오).
- **폴백 사다리.** L1 긍정 → U0 그대로. L1이 B 등급만 문제 삼으면 → ext 세계에서 B를 끄고 A만 쓴다(품질 손실은 X-FF 진단으로 보고). L1이 A까지 문제 삼으면 → **회사 계정 EXTGEN만** Plan A 사람 전사(v2.1 A 경로: 사람이 WorldScript와 θ를 적고 엔진이 픽셀 피팅 없이 짓는다)로 내린다. USER 업로드는 사용자가 생성기 약관의 당사자이고 보증 조항이 있으므로 경로를 유지하되, L1 결론을 약관 안내에 반영한다. 어느 경우에도 Phase 1 목표는 PUB(Soul 0)에서 판정되므로 바뀌지 않는다.

#### F-R6. 발명 표시 과소와 첫 프레임 주장

- **무엇이.** 원 메모 §2.4의 가시 라벨은 "AI로 재구성한 장면 · 입력에 없던 영역 N%"였고, N은 IR_geo(입력이 관측하지 않은 면적)였다. "입력이 흐리게만 본 곳을 선명하게 보여 주는 것"도 발명이다(IR_info, 파이프라인 F-P6).
- **숫자.**

| 상황 | IR_geo | IR_info@납품 | 계산 |
|---|---|---|---|
| 2K 입력 → 1080p 정지 | 0 | 0 | 2048 ≥ 1920 |
| 2K 입력 → 4K 정지 | 0 | **0.72** | 1 − (2048/3840)² = 0.716 |
| 2K 입력 → 8K 정지 | 0 | **0.93** | 1 − (2048/7680)² = 0.929 |
| 2K → 1080p 푸시인 m 1.5 | 0.01–0.03 | 끝 0.49 / 평균 0.25 | 파이프라인 F-P6 |
| 녹은 배경으로 랙 포커스 | 0.01 | 0.5–0.7 | 같음 |
| 🔴 180° 오빗 | 0.75–1.0 | ≥ IR_geo | 벤치 §2.3 |

- **업그레이드 1: 두 수치 라벨 [CT-R10].** 가시 라벨은 "AI 재구성 · 형태 발명 x% · 디테일 발명 y%"다. x = 클립 평균 IR_geo, y = 클립 평균 IR_info@납품 해상도. 최대값은 사이드카에 둔다. 메뉴 등급(파이프라인 CT-I15: IR_pred = max(IR_geo, IR_info))과 같은 수치를 쓴다.
- **업그레이드 2: 발명 지도 2채널.** 사이드카 마스크는 채널 0(미관측), 채널 1(관측 대역 위 합성)을 따로 싣는다. 부동산 범주는 화면 표시를 강제한다.
- **업그레이드 3: 주장 장부 규칙.** "8K"는 "8K 렌더(입력 대역 2K, 그 위 93%는 합성)"처럼 입력 대역을 병기한다. MTF50@8K 주장은 8K 네이티브 I-OWN 입력(벤치 8장)에서만 한다. "사진 그대로 시작" 주장은 첫 프레임 지각 거리(FFD)가 사전 등록 임계 아래인 클립 비율과 함께만 쓴다. Read-Only Camera(첫 프레임 바꿔치기·크로스페이드 금지)는 그대로다.
- **게이트.** D45 라벨 감사: 표본 100클립에서 라벨 y와 재계산 IR_info의 차이 ≤0.02.

#### F-R7. 출처 사슬의 개인정보 누출과 검증 충돌

- **무엇이 (세 갈래).**
  1. **C2PA 재료.** 원 메모는 입력의 C2PA 매니페스트를 출력의 재료(ingredient)로 이어 붙였다. 카메라·편집기 매니페스트에는 위치, 작성자, 기기 단언이 들어갈 수 있다(추정, 기기별). EXIF에서 GPS를 지워도 재료 매니페스트로 다시 실린다. 사용자가 "Soul로 만든 사진"이라는 사실을 숨기고 싶을 수도 있다.
  2. **Proof-of-Shot 입력 해시.** 무염 SHA-256(입력)은 원본 사진을 가진 사람이 공개 영상과 그 사진을 이을 수 있게 한다.
  3. **워터마크 대 비트 동일.** 비밀 키 비가시 워터마크를 넣으면 외부인은 워터마크 후 비트를 재현할 수 없다. "왕복 비트 동일(검증 파일 공개)"과 Kaggle 재현이 깨진다.
- **일정.** EU AI Act 제50조 기계판독 표시 날짜(원 메모 기준 2026-12-02 [2차])가 90일 창 안(약 D50–55)이다. P1은 EU 서비스가 없어 제공자 의무는 직접 걸리지 않을 수 있다. 그러나 실사 장소·인물 데모를 공개하면 배포자의 딥페이크 고지(제50조 4항) [2차]가 걸릴 수 있다.
- **업그레이드 1: 재료 가림 기본 [CT-R7 개정].** C2PA 사양의 단언 가림(redaction) [부품]으로 재료 매니페스트의 위치·작성자·기기 식별 단언을 지운다. 남기는 것: 행위(actions), 디지털 출처 유형, claim generator, 해시 바인딩. 사용자가 원하면 전체 사슬을 켠다.
- **업그레이드 2: 솔트 커밋.** Proof-of-Shot의 입력 항목 = H(s ‖ input), s는 프로젝트별 128 bit 난수다. s는 user_vault와 사용자에게만 있다. 사용자가 원할 때 s를 공개해 출처를 증명한다.
- **업그레이드 3: 키 분리 워터마크.**

| 용도 | 키 | 결정론 | 외부 검증 |
|---|---|---|---|
| 벤치·데모 공개본 | **공개 벤치 키 k_pub**(키 자체를 공개) | WM(render, k_pub)는 결정론 | 검증기가 다시 렌더 → PoS의 워터마크 전 해시 일치 → WM(·, k_pub) 적용 → 공개 파일과 비트 비교 |
| 제품 출력 | 비밀 키 k_P(KMS) | 결정론 | 우리 탐지 API만 |

  - 공개 키 워터마크는 누구나 지우거나 위조할 수 있다. 벤치 공개본은 서명된 C2PA와 PoS가 진위를 맡으므로 괜찮다.
  - 비용: 8K 프레임 워터마크 삽입 10–30 ms(추정), 8 s × 24 fps = 192프레임에 2–6 s.
- **게이트.** 결정 시점을 D53에서 **D45**로 당긴다. D60 대결 릴이 첫 공개물이기 때문이다.

#### F-R9. 벤치 권리 사슬

- **(a) 인물 동의 대 CC BY.** 벤치 렌즈는 I-OWN을 CC BY 4.0으로 배포한다. CC BY는 철회할 수 없다. 개인정보보호법상 동의는 철회할 수 있다. C5(사람 포함) I-OWN 6장과 다른 범주의 식별 가능한 인물 사진이 문제다.
  - **업그레이드.** 인물이 식별되는 I-OWN은 (i) 유급 모델 릴리스(영구 공개 배포·AI 벤치·크라우드 평가·국외 API 전송을 명시, 인당 $50–150)를 받거나, (ii) **벤치 라이선스**(평가·연구 사용, 삭제 요청 시 다음 판에서 제거, 재배포 때 최신판 사용 의무)로 낸다. 인물 없는 사진만 CC BY 4.0이다.
- **(b) 국외 API 전송과 회차 오염.** T2는 같은 입력을 Kling·Seedance·Veo·Wan에 넣는다. 식별 가능한 인물이 든 사진을 국외 벤더에 보내는 것은 제3자 제공·국외 이전이다. 벤더가 입력으로 학습하면 다음 회차 벤치가 오염된다.
  - **업그레이드.** **PUB-open**(공개 재현용, 회차를 넘어 고정)과 **PUB-sealed**(회차마다 새로 찍은 ≥30%, 측정 전 비공개, 측정 후 공개)로 나눈다. 승리 주장은 두 집합 모두에서 성립해야 한다. 봉인분은 입력 무학습 조건이 확인된 벤더 등급을 우선한다. 벤더 데이터 조건 표(§3.2)를 D7에 채운다.
- **(c) 호스팅 경유 금지.** Higgsfield는 Kling·Veo·Seedance·Wan을 호스팅한다. 창업자 구독으로 경쟁 클립을 뽑으면 (i) 5.1(iii)(출력으로 경쟁 서비스 개발) 독해 위험, (ii) 4.4(Higgsfield가 입력으로 자기 모델 학습)로 우리 벤치 입력·인물 사진이 넘어간다. **경쟁 클립은 각 벤더의 1차 API에서만 뽑는다.** 재판매·호스팅 플랫폼은 약관 확인 전 금지다.
- **(d) 워터마크.** 벤치 렌즈는 블라인드 평가에서 보이는 워터마크를 A·B 같은 위치에 같은 크기로 가린다. 내부 평가는 괜찮다. **공개본에는 가린 클립을 쓰지 않는다.** 원본 그대로 싣고 모든 패널에 "AI 생성(모델명, 버전, 날짜)"을 단다. 재인코딩으로 사라진 경쟁 C2PA는 comp_vault 원본에 남겨 두고 그 사실을 적는다.
- **(e) W 트랙 라이선스 게이트.** 벤치 W 트랙(이미지 → 세계)의 후보는 약관부터 확인한다.

#### F-R10. 에셔 쇼케이스와 KPI 공개

- **무엇이.** I2V 결정 §3.3은 덤 쇼케이스로 "AI 이미지 원근 거짓말 탐지기"를 제안했다. X-ESC-α는 출처당 10장이다. 비율 p의 95% 신뢰구간 반폭은 1.96·√(p(1−p)/n)이고, n = 10, p = 0.5면 ±31%p다. 이 숫자로 "생성기 X는 원근을 30% 속인다"를 공개하면 비교 광고·명예 문제가 되고 통계로도 방어하지 못한다.
- **두 번째 구멍.** I2V 결정 §3.1은 발명 비율을 "공개 보고"하라고 했다. 사용자 집계(TEL-CAGG)는 셀당 k ≥50이 조건이다. P1은 창업자·내부 테스터만 업로드하므로 셀을 채우지 못한다.
- **업그레이드.**

| 공개물 | 입력 | 조건 |
|---|---|---|
| 탐지기 데모 | CAPTURE, CC0·PD, OPEN-GEN | 언제나 가능 |
| 생성기 이름을 건 통계 | 회사 계정으로 만든 EXTGEN | **생성기당 n ≥100**(p = 0.5에서 ±9.8%p), 사전 등록, 같은 프롬프트 세트, L8 검토. 그 전엔 "생성기 A–D" |
| 에셔·IR·FFD KPI | PUB(open + sealed) | P1의 공개 KPI는 PUB에서만 |
| USER 집계 KPI | TEL-CAGG | 베타 이후, 셀당 k ≥50 |
| 개별 업로드의 에셔 점수 | USER-DERIVED | 그 사용자 화면에만. 공개 데모 금지(파이프라인 F-P10 (g)) |

- **비용.** 생성기당 100장 × 4곳 = 400장. 회사 계정 생성이 필요하다. Soul은 상한 500장 밖이라 쓰지 않는다. 오픈 생성기와 GPT Image 등 저가 출처로 먼저 한다(<$50 수준, 벤치 §4.8 기준). 일정은 `P1-확장`이다.

#### F-R13. 교사 암기 역류가 ENGINE을 오염시킨다

- **무엇이.** 파이프라인 F-P11은 발명 영역에서 교사가 상표·작품·랜드마크를 역류시키는 위험을 다뤘다(데모 쪽). 이 렌즈가 보는 것은 **학습 쪽**이다. 원 메모는 엔진 교사 출력을 `ENGINE`(학습 가능)으로 분류했다. 역류한 IP가 TexelFM 래칫, D2-O 4천 장, SI 세계로 들어가면 "깨끗한 학습 데이터"라는 주장이 깨진다. Apache-2.0 §7–8은 보증을 부인하고 책임을 제한한다. 출력 IP 위험은 우리가 진다.

#### F-R15. 파트너십 창이 닫힌다

- **무엇이.** 원 메모 §4.6의 재접촉 트리거 다섯 개(데모 릴, PUB 벤치 결과, 법인·도메인·회사 메일, 약관·처리방침 v1, L1 의견)가 모두 충족돼야 접촉한다. PUB 벤치 결과는 D90이다. 그러면 접촉은 D90 뒤다. 그사이 Higgsfield는 웹 3D 장면 빌더를 키우고 경쟁 I2V를 계속 호스팅한다 [2차]. 그들이 자체 "이미지 → 세계"를 내면 유통 제안의 가치가 떨어진다.
- **업그레이드: 2단 접촉.**

| 단계 | 시점 | 필요 조건 | 내용 |
|---|---|---|---|
| 소개 | **D60–65** | 법인·회사 메일(Q34로 D55 전), 대결 릴 v0(PUB 입력), "세계로 열기" 통합 명세 1쪽, 데이터 조건(ECF 요약, DPA v0) | 관계 개설. 요청은 "통화 한 번" |
| 제안 | D90+ | PUB 벤치 결과(사전 등록), L1 의견 | §4.6 제안 골자 |

- **다중 유통.** 의존 0 원칙에 맞게 비독점 유통 후보를 2–3곳 병행한다(이미지 생성 앱, 크리에이티브 툴, 오픈 모델 호스팅 플랫폼). 어느 곳과도 독점하지 않는다.
- **창업자 결정과의 정합.** 창업자는 도메인·회사 메일·폼 재접수를 데모 이후로 보류했다. 이 개정은 그 순서를 지킨다. 다만 Q34(공개 데모 전 법인 설립)가 법인과 메일을 데모 직전에 만들게 하므로, 소개 접촉이 데모 직후(D60–65)로 자연히 당겨진다(Q38).

# 개정 메모 본문

## 0. 결론 요약 [개정]

1. **"라이선스는 필요 없지만 의무는 생긴다."** 사용자가 자기 이미지를 넣고 영상을 받는 추론에는 생성기 회사의 허락이 필요 없다. 확인한 주요 생성기 약관은 모두 출력 소유권을 사용자에게 두거나 주장하지 않는다(§3.1). 우리는 그 약관의 당사자도 아니다. 대신 업로드를 받는 순간 네 가지 의무가 생긴다. 권리 보증, 개인정보, AI 생성물 표시, 신고 처리다. [개정] 인물이 나오면 다섯째 의무(딥페이크 표시·생체정보)가 붙는다(§2.5).
2. **Soul 방화벽을 사용자 콘텐츠 방화벽(ECF, External Content Firewall)으로 일반화한다.** soul 비트를 ext 비트로 넓힌다. ext=1인 모든 계산은 클린룸 레인에서 돌고, 학습·보정·전역 은행·공유 프리셋으로 흐르지 않는다. 태그는 `USER`, `USER-DERIVED`, `EXTGEN:<생성기>`, `COMP`, `HOLDOUT` 등으로 확장한다. [개정] 클린룸은 프로세스만이 아니라 메모리·캐시·외부 연산까지 격리한다(§1.4.1).
3. **1-입력 원칙.** 이미지 한 장에 세계 W를 피팅해 그 이미지의 영상을 만드는 것은 추론이다. 파라미터는 그 입력에만 쓰고, 다른 입력으로 넘어가지 않고, 프로젝트와 함께 삭제한다. v2.1 회색지대(CT33) "Soul 스틸 관측 피팅"이 이 원칙으로 Plan A 안으로 들어온다. [개정] W의 파라미터를 A(명시 장면)/B(장면별 신경 표현)/C(공유 가중치)로 등급화하고 작업 명세서로 법무 의견(Q27, L1)을 받는다.
4. **개발 방화벽.** Higgsfield 5.1(iii), Google 약관, Midjourney §1 때문에 외부 생성기 출력은 학습뿐 아니라 개발 루프에도 넣지 않는다. [개정] 규칙은 **PnP(우선순위는 되고 파라미터는 안 된다)**다. COMP·EXTGEN·TEL-CAGG는 판정(J)만 하고, 선택(S)은 GT·자체 데이터로만 한다. 프록시 사다리 P0–P4로 결함을 재현한다(§3.3).
5. **학습 원천은 셋뿐이다.** `ENGINE`, `CAPTURE`, `ASSET`(+ 그 파생 SI·OPEN-GEN 학습분·TWIN·COMMISSION 학습권). 사용자 세계는 래칫 밖이다. 플라이휠은 Self-Input 래칫으로 돈다. [개정] ENGINE도 암기 역류 가드(`IP-FLAG`)를 통과해야 학습에 들어간다.
6. **학습에 쓸 수 있다고 확인된 외부 이미지 출처는 Apache-2.0 오픈 모델뿐이다.** Z-Image-Turbo([검증])와 FLUX.2 [klein] 4B다. FLUX [dev] 계열은 출력으로 경쟁 모델 학습을 금지한다. Higgsfield, Google은 명시적으로 금지한다. OpenAI, Midjourney는 경쟁 조항이 있다. 나머지는 미확인이다(§3.1). [개정] HunyuanWorld 라이선스는 한국을 영역에서 빼고 출력으로 다른 모델 개선을 금지한다 [검증]. SEVA는 비상업이다 [검증].
7. **Soul은 핵심 의존성에서 선택적 입력원·파트너로 내려간다.** MCP 자동 호출은 0이다. Soul 경유 POLISH와 X-Soul은 폐기한다. [교정: NC-R1] 웹 수동 생성은 90일 **75–510장, 상한 500장**이다. 데모 입력, 벤치 I-CLOSED, 에셔 테스트, 키 아트에만 쓴다(§4.4).
8. **승인 단계 재정의.** U0(추론·콘텐츠) / U1(교차 입력 재사용·공개) / U2(학습). [개정] Soul 입력을 경쟁 API에 넣는 공개 대결은 U1이다. 기본 공개 대결은 T1형이다(§4.3).
9. **Higgsfield는 보류.** 내용 거절이 아니라 접수 경로 문제다(티켓 #317768). [개정] 법인 설립(Q34) 직후 **소개 접촉 D60–65**, 벤치 결과 뒤 **제안 D90+**의 2단으로 한다. 제안은 비독점 유통 파트너십("세계로 열기")이다(§4.6).
10. **T2V 입구.** 제품은 이미지 전용(+ 선택 텍스트)으로 연다. 엔진 hero는 내부 전용이다. [교정: NC-R5] 내부 hero는 선택 없이 장당 약 8 TFU다(§5).
11. **모델 중립은 증명 가능한 주장이어야 한다.** 감사 로그, 카나리아 7종, 투명성 보고서로 뒷받침한다. 공개 주장은 모두 주장 장부에 묶는다. [개정] "8K", "사진 그대로 시작", 생성기 이름을 건 통계에 장부 규칙을 더한다(§6.4).
12. **규제 일정.** 한국 AI 기본법 제31조 표시 의무(2026-01-22 시행, 과태료 계도 1년 이상) [2차], EU AI Act 제50조 투명성 의무(2026-08-02 적용, 기계판독 표시는 기존 시스템에 한해 2026-12-02까지 유예) [2차], 미국 TAKE IT DOWN Act 신고·48시간 삭제(2026-05-19부터 FTC 집행) [2차]. 대응은 C2PA 출처 표시 + Proof-of-Shot + 발명 지도 + 가시 라벨이다. [교정: NC-R16] 워터마크 결정은 D45다.
13. **[신규] 벤치 입력의 권리 사슬은 벤더와 평가자까지 이어져야 한다.** PUB-open/PUB-sealed 분리, 인물 사진 모델 릴리스 v2, 1차 벤더 API만, 공개본 워터마크 무가림(§4.3).
14. **[신규] 숫자는 원장 하나에 있다.** Soul 상한, 법무, 권리 취득, 권리 렌즈 T4-h(6–11)는 이 렌즈 소유로 수치 원장에 등록한다(§7.4).

- **v2.1 태그와의 대응.** `SOUL` = `EXTGEN:soul`, `SOUL-DERIVED` = `EXTGEN-DERIVED:soul`, `SOUL-INSPIRED` = `EXTGEN-INSPIRED:soul`. 코드와 문서는 새 이름을 쓰고 별칭표에 옛 이름을 남긴다(CT39 원칙). 파이프라인 원 메모의 `src ∈ {USER, PARTNER, OWN, CC0, ENGINE}`은 PARTNER → `EXTGEN:<g>`, OWN → `CAPTURE`, CC0 → `ASSET(CC0)`, 벤치분은 + `HOLDOUT`으로 옮긴다.
- **사용자 콘텐츠에는 INSPIRED가 생기지 않게 한다.** 엔지니어는 사용자 콘텐츠를 보지 않는다(§1.4 브레이크글라스). CI는 사람이 본 것을 감지하지 못하므로 접근 통제와 접근 로그로 막는다.
- **TEL-CAGG의 자리.** "데이터에서 파생된 데이터"를 학습에 쓰는 것도 막는 약관이 있다(Higgsfield 5.2(iv) "any data derived therefrom"). 그래서 콘텐츠 파생 집계는 사람이 읽는 보고서와 공개 KPI로만 쓰고, 생성기·선택기 조정 신호로 쓰지 않는다. [개정] 사람이 보고서를 읽고 학습 분포를 맞추는 것도 조정이다(F-R3). 보고서는 우선순위만 정한다.
- **프롬프트는 입력이다 [신규].** 우리가 외부 생성기에 넣은 프롬프트 텍스트는 우리 입력이고 출력 제한을 받지 않는다(Higgsfield 4.4 입력 소유). SI 입구 생성에 같은 프롬프트 목록을 써도 된다. Soul 결과를 보고 고친 이력은 기록한다.

### 1.3 prov 필드, 전파 규칙, 1-입력 원칙 [개정]

**STRATA 블록 필드.** v2.1의 `own`, `meta.prov`를 넓힌다.

```
meta.prov = {
  taint:  set[Tag],            # §1.2
  mode:   none|inspired|derived|authored,
  roots:  set[UploadID|AssetHash],   # 삭제 폐포 계산용
  ns:     user_vault|ext_vault|comp_vault|pub_bench|train_ok,
  src:    {gen, model, version, date, plan, account, terms_hash, c2pa_claim?},  # EXTGEN·USER(가능한 경우)
  wclass: A|B|C                # [신규] 갱신된 파라미터의 등급(F-R5)
}
ext  = |taint ∩ {USER, USER-DERIVED, BIO, EXTGEN:*, EXTGEN-*}| > 0
comp = COMP ∈ taint ;  hold = HOLDOUT ∈ taint
Merkle 키 ∋ (ext, comp, hold, ns)                         # v2.1의 soul 비트 자리
Merkle 내용 주소 = HMAC(K_P, bytes) if ext else SHA-256(bytes)   # [신규] 테넌트 간 중복 제거 금지(F-R12)
```

**전파 규칙 (의사코드).**

```
def derive(op, parents, human_ref=False):           # human_ref: 참조 행위(나란히 맞춤·전사·측정)
    x.taint = ⋃ p.taint for p in parents
    x.roots = ⋃ p.roots for p in parents
    x.mode  = 'inspired' if human_ref and any(p.ext for p in parents) else max(p.mode for p in parents)
    x.ns    = most_restrictive(p.ns for p in parents)   # user_vault > ext_vault > comp_vault > pub_bench > train_ok
    if op.updates_shared_weights and x.ext: raise FirewallError('CT-M5')   # [신규] C 등급 금지
    return x

BLOCK_TRAIN = {USER, USER-DERIVED, BIO, EXTGEN:*, EXTGEN-DERIVED:*, COMP, HOLDOUT, EVAL-ONLY, D3, NC}
BLOCK_DEV   = {USER, USER-DERIVED, BIO, EXTGEN:*, EXTGEN-DERIVED:*, COMP, EVAL-ONLY}

def train_ok(x, branch='main'):
    if branch == 'main':
        return (not (x.taint & BLOCK_TRAIN)
                and not (x.mode == 'inspired' and has_ext_ancestor(x))        # Q17
                and not unmasked(x, IP-FLAG)                                  # [신규] F-R13
                and all(role(g) == 'train' for g in open_gens(x))             # [신규] 홈/어웨이
                and all('train' in scope(c) for c in commissions(x)))         # [신규] F-R14
    if branch == 'optin-v1':                                                  # 장기
        return x.taint <= {CAPTURE, ENGINE, ASSET, HUMAN, OPTIN} and optin_valid(x.roots)

def dev_ok(x):         # 회귀셋, 튜닝, HP·체크포인트·프리셋 선택, 자동 2AFC 보상
    return not (x.taint & BLOCK_DEV) and all(role(g) in ('train','dev-eval') for g in open_gens(x))

def signal_class(x):   # [신규] PnP 규칙(CT-R9)
    return 'S' if dev_ok(x) else 'J'

def eval_report_ok(x): # R-EVAL: 별도 프로세스, 결과는 사람이 읽는 보고서·결정 기록·공개 KPI뿐
    return True

def delete_project(P):
    if legal_hold(P): reencrypt_evidence(P, K_hold); return           # [신규] 신고·법적 보존 우선
    destroy(K[P])                                   # ≤24h, 백업까지 읽을 수 없게 됨
    gc({y : y.roots ∩ uploads(P) ≠ ∅})              # ≤7d, 주 저장소와 캐시
```

**1-입력 원칙 [운용].** 다음 네 조건을 모두 지키는 최적화는 "모델 학습"이 아니라 그 입력에 대한 추론(테스트타임 최적화)으로 본다. 이 해석이 CT-R2이고, 법무 의견으로 확정한다(Q27, L1).

| # | 조건 | 강제 수단 |
|---|---|---|
| 1 | 최적화되는 파라미터는 그 입력의 장면 표현(W, θ_in, 조명, 견본)뿐이다. 공유 가중치(G-Adapter, MRH, TexelFM 등)에는 그래디언트가 0이다 | 클린룸 레인에서 공유 가중치는 **봉인 memfd 읽기 전용**으로 매핑, 마운트 때 해시 검증 [개정] |
| 2 | 결과는 그 입력의 요청자에게만 쓰인다. 다른 프로젝트·사용자로 넘어가지 않는다 | ns = user_vault, 프로젝트 키 암호화, [개정] HMAC Merkle |
| 3 | 어떤 학습·개발·전역 은행으로도 흐르지 않는다 | Lineage CI(§1.5), 카나리아(§1.6) |
| 4 | 프로젝트 삭제 때 함께 삭제된다 | crypto-shredding, 삭제 카나리아 |

**W 파라미터 등급표 [신규, CT-R2 개정].**

| 등급 | 무엇 | 예 | 판정 | 추가 조건 |
|---|---|---|---|---|
| A 명시 장면 | 해석 가능한 장면 값 | STRATA 블록, splat(0.4M × 14–58 = 6–23M), 텍스처 페이지, 메시, 해석 조명, θ_in, 견본 | U0 | 조건 1–4 |
| B 장면별 신경 표현 | 그 장면 전용 작은 신경장·잠재 코드 | 해시 그리드 + 작은 MLP 텍스처 | U0 | B1 파라미터 수 ≤ 그 세계 샘플 수, B2 읽기 전용 초기화 또는 고정 seed, B3 재사용 0, B4 삭제 폐포 안 |
| C 공유 가중치 | 여러 세계가 쓰는 모델 | 교사, MRH, TexelFM, G-Adapter, LoRA, 헤드 | **금지** | 카탈로그 CT-M5. TTT·온라인 헤드 학습·세계별 LoRA 포함 |

- **정직한 숫자.** splat 장 6–23M은 2K 입력 관측값 7.1M과 같은 규모다. 그러나 파라미터 대부분은 교사가 지은 발명 영역에 맞춰지고, 장면 하나 말고는 아무것도 만들지 못한다(일반화 0). L1 질의는 이 숫자와 함께 작업 명세서로 보낸다(F-R5).
- **회사 데모에도 같은 원칙이 적용된다.** 창업자가 Soul 스틸로 데모 세계를 짓는 것은 조건 1–3을 지키는 한 U0다. 조건 4 대신 ext_vault에 보존한다(회사 콘텐츠이므로).
- **교차 입력 재사용은 U1이다.** 예: Soul 입력에서 자동 추출한 θ를 공유 프리셋 라이브러리에 넣어 다른 세계에 쓰는 것. 이것은 모델 학습은 아니지만 "데이터를 다른 입력으로 옮기는" 행위라 약관 해석 대상으로 남긴다.
- **L1 폴백 사다리.** 긍정 → U0. B만 문제 → ext 세계는 A만. A까지 문제 → 회사 EXTGEN은 Plan A 사람 전사, USER는 보증 조항과 안내 갱신. Phase 1 판정은 PUB에서 하므로 목표는 그대로다.

### 1.10 옵트인 학습을 한다면: 조건 [`장기`]

창업자 규칙은 "출처 생성기 약관 확인 불가 시 금지"다. 업로드 이미지가 어느 생성기에서 왔는지는 확인할 수 없다(C2PA는 지워지거나 위조된다. Higgsfield 한 곳만 해도 50개 넘는 모델을 호스팅한다 [2차]). 그래서 AI 생성 이미지는 사실상 대상이 아니다.

| # | 조건 | 판정 |
|---|---|---|
| 1 | **대상은 사용자가 직접 촬영한 실사 사진(CAPTURE-USER)만.** 사용자가 "AI 생성·AI 편집 아님"을 진술 | 필수 |
| 2 | 진술과 증거가 맞을 것: 카메라 EXIF 일관성, C2PA에 AI 생성 주장 없음, (선택) RAW | 불일치면 제외 |
| 3 | 인물이 탐지되면 제외(동의서 업로드 기능 전까지). 미성년자 의심이면 무조건 제외 | 필수 |
| 4 | 위치·기기 정보 제거 | 필수 |
| 5 | 약관과 분리된 별도 동의, 항목·목적·보유기간 명시, 언제든 철회 | 필수(개인정보보호법상 별도 동의 원칙) |
| 6 | **철회 시 기여 제거:** 해당 루트가 든 샤드를 빼고 영향받는 모델만 다음 정기 재학습(≤30일)에서 다시 학습한다. 수십M 모델이라 가능하다. 예: TexelFM-35 한 세대 약 90 T4-h(v2.1 §5.6) | 필수. 약관에 "이미 배포된 모델은 다음 재학습까지 남는다"를 적는다 |

- **판정: P1·P2에서는 옵트인 학습을 열지 않는다.** 래칫은 Self-Input으로 충분히 돌아야 한다(§1.11). 옵트인은 실사 시장(§6.3)의 분포 차이가 측정으로 확인될 때 연다.

### 1.11 래칫 영향과 Self-Input 래칫 [조합] [개정]

- **문제.** I2V에서 운영 트래픽은 전부 ext=1이다. v2.1 플라이휠(관할 이양 래칫)은 사용자 데이터를 한 바이트도 먹지 못한다. 경쟁사는 사용자 업로드로 학습하는 경우가 많다(Higgsfield 4.4, BFL API 약관 [검증·2차]). 우리는 그 길을 스스로 닫는다.
- **해법: Self-Input 래칫.** 엔진이 사용자 입력과 같은 모양의 가짜 입력을 만들고, 그 입력으로 사용자와 똑같은 I2V 경로를 돈다. 결과 세계는 `SI` 태그로 래칫에 들어간다.

```
SelfInput(prompt p, style s):
  x_in ← EngineHero(p, survey=False, look=s)        # Z-Image(Apache) 또는 klein 4B(Apache), 선택 없이 seed 1장(장당 약 8 TFU)
       | PhysLook(world, θ_cine)                   # [신규] 엔진 세계를 시네 θ로 렌더(프록시 P0, 정답 θ 보유)
       | CaptureOwn(scene)                          # 자체 촬영 실사(시네 지침 포함, 프록시 P1)
  assert lint_prompt(p)                             # [신규] 금칙 목록(F-R13)
  x_in ← Perturb(x_in; escher_defect ~ q, grain, grade, crop)   # q의 basis ∈ {PHYS, CAPTURE, ASSET, OPEN-GEN(train)}
  W    ← I2W(x_in)                                   # 사용자 경로와 같은 코드, 단 ns = train_ok
  if glyph_ip_scan(W) : W.taint |= {IP-FLAG}         # [신규] 가림 후 래칫
  Ratchet.add(W, tag=SI)                             # ext = 0
```

- **분포 맞추기 [교정].** 원 메모는 "가짜 입력 분포를 실제 입력 분포에 맞추는 신호는 TEL-SYS와 사람이 읽는 TEL-CAGG 보고서뿐"이라고 적었다. 이것은 사람을 통한 파생 데이터 사용이다(F-R3). **q와 교란 범위는 근거 화이트리스트(물리 범위, CAPTURE, CC0·PD, 학습용 OPEN-GEN 측정)로만 정하고 D7에 사전 등록한다.** TEL-SYS와 TEL-CAGG는 "어떤 부류를 먼저 늘릴지"(우선순위, J)만 정한다.
- **물량 [교정: NC-R6].** 벤치 §4.6 세계 솔브 버킷의 **라이브러리 dev 160 세계(240 T4-h, 평균 1.5 T4-h)가 SI 전량**이다. 따로 잡지 않는다. 벤치 세계(160 + 안전 재건 64)는 HOLDOUT이라 래칫에서 빠진다.
- **정직한 한계.** SI 입력은 Soul·GPT Image 같은 실제 AI 이미지의 "개념 기획"을 흉내 내지 못한다(A/B에서 Z가 진 축). 그래서 개념 축의 분포 차이는 남는다(R44). 대응은 동결 측정(J)으로 차이를 재고, 프록시 사다리(§3.3)를 올리고, 차이가 크면 파트너 계약 U2(§4.2)로 연다.

### 3.3 개발 방화벽, PnP 규칙, 프록시 사다리 [신규 운용, CT-R3·CT-R9·CT-R14] [개정]

- **문제.** 학습 금지만으로는 부족하다. Higgsfield 5.1(iii)과 Google 소비자 약관은 "개발·개선"에 출력을 쓰는 것 자체를 막는다. 엔지니어가 Soul 입력에서 깨진 사례를 보고 코드를 고치고, 그 이미지를 회귀셋에 넣고, 그 이미지로 하이퍼파라미터를 고르면 "출력으로 경쟁 서비스를 개선"한 것으로 읽힐 수 있다.
- **구분.** *콘텐츠 제작 조작*(그 데모 세계의 W·샷·조명·θ 파라미터, 사람 연출)은 콘텐츠 사용이다. *시스템 변경*(코드, 가중치, 하이퍼파라미터, 회귀셋, 프리셋 라이브러리)은 개발이다.
- **[개정] 자기모순과 해소.** 원 규칙을 그대로 읽으면 COMP로 판정하는 Day-90 게이트와 "실패하면 업그레이드"도 개발 사용이다. 그래서 작동 단위를 신호로 바꾼다(PnP, P.2 F-R2 표).
- **규칙.**
  1. EXTGEN·USER·COMP·EVAL-ONLY 항목은 회귀셋, HP 탐색, 체크포인트·프리셋·교사 선정, 자동 2AFC 보상에 들어가지 않는다(CI 규칙 8, 카나리아 C5).
  2. 측정은 **동결 평가**로만 한다. 코드가 동결된 버전으로 한 번 돌리고, 결과는 사람이 읽는 보고서(R-EVAL)와 결정 기록으로만 남긴다.
  3. **[개정] PnP.** 위 출처의 결과는 J 신호(합격·불합격, 녹/황/적, 우선순위)로만 쓴다. 업그레이드의 "어떻게"(arm, 파라미터, 임계)는 S 신호(GT, 절대 지표, dev_ok 출처)로만 고른다. PR 템플릿에 두 칸을 둔다. COMP 게이트 조회는 D30·D60·D90 3회(누적 ≤4.8 bit)다.
  4. **프록시 재현.** EXTGEN 입력에서 발견한 결함을 고치는 변경은, 같은 결함을 ENGINE·SI·CAPTURE·PUB-open·TWIN 입력에서 재현한 사례를 PR에 붙여야 병합된다. [개정] 재현은 **프록시 사다리**(P0 PhysLook → P1 CAPTURE-cine → P2 OPEN-GEN-cine → P3 의뢰 → P4 파트너, P.2 F-R4 표)를 오른다. P0–P2에서 못 하면 "고치지 않는다"가 아니라 P3 의뢰로 올린다.
  5. 프록시 생성기: Z-Image 또는 klein 4B에 "Soul풍" 시네마 프롬프트와 θ_look을 준 출력(v2.1 E3 (c) Soul풍 대리 판독의 일반화), §1.11의 에셔 결함 주입, [개정] PhysLook 렌더(물리 8축, 정답 θ).
- **결함 분류 코드.** R-EVAL 보고서는 고정 코드로 결함을 적는다(예: `ESC-STAIR`, `LOOK-ANAMORPH`, `DOF-SWIRL`, `FACE-SIDE`, `REFL-TATTOO`). 프록시 라이브러리는 같은 코드로 미리 색인한다. 쌍둥이 검색이 수동 재현을 대신한다.
- **비용 [교정].** 원 메모는 프록시 재현 1건 0.5–2 h(추정)만 적었다. 90일 약 60건이면 30–120 h다. 코드 색인 뒤 건당 0.25–1 h(추정), 15–60 h다. 평가·사람 연구 1.5 FTE 안에서 쓴다. P0 렌더 1천 장 약 0.2 T4-h, P2 생성은 장당 약 8 TFU다.
- **격차 게이트(J).** D60 Δ = VP(INT-soul) − VP(PUB-away). Δ < −10%p면 사다리를 한 단 올린다.
- **완화 조건.** 법무 의견이 "개발"을 좁게 해석하면(예: 비학습 테스트는 개발이 아니다) 규칙 2–4를 완화한다. 1은 유지한다.

## 4. Soul의 v3 역할과 Higgsfield 부록 v3

### 4.1 역할 변화

창업자 결정은 "Soul은 버리지 않는다"(v2.1)와 "Soul 없이도 된다"(I2V)를 함께 성립시킨다. Soul은 **핵심 의존성이 아니라 가장 좋은 입력원 가운데 하나**가 된다. I2V에서 개념과 룩은 입력 이미지가 소유한다. 그 입력이 Soul이면 Soul의 미감이 첫 프레임을 소유하고, 우리는 그 미감을 무너뜨리지 않고 카메라를 움직인다.

외부 생성기 모두에 쓰는 일반 사다리로 바꾼다. Soul의 v2.1 단계는 아래처럼 대응한다.

### 5.3 추천과 근거, 뒤집힐 조건

**추천: O1(이미지 전용)을 P1 제품 입구로, O2는 파트너 계약 형태로 `P1-확장`, 엔진 hero는 내부 전용(O3 비노출).**

| 근거 | 내용 |
|---|---|
| 미감 | 첫 프레임은 사용자가 가장 먼저 판단하는 것이다. 엔진 hero는 50축 중 1승이다. 이미지 모델 경쟁에 참전하지 않으면 그 1승을 보여 줄 일도 없다 |
| 권리 | 우리가 이미지를 생성하지 않으면 생성 프롬프트 심사와 이미지 생성물 표시 범위가 줄어든다. 남는 것은 업로드 심사와 영상 표시다. [개정] 출력 IP 위험(교사 암기 역류)도 내부로 한정된다 |
| 중립 | 우리 T2I가 없어야 "이미지 모델 전쟁의 스위스"가 말이 된다 |
| 컴퓨트 | hero 오디션 112 TFU 절감(v2.1 기준 16%) |
| 벤치 | 같은 첫 프레임 대결(T2)이 공정하다. T2V 비교가 필요하면 "T2V-합성(사용한 T2I 이름)" 트랙으로 표기한다 |

**뒤집힐 조건.** (1) TEL-SYS 퍼널에서 "이미지 없음"으로 이탈하는 비율이 높고 파트너 통합이 늦을 때(임계값은 창업자가 정한다), (2) Apache 오픈 이미지 모델이 개념 축까지 이길 때(측량 교사 재오디션에서 확인, 카탈로그 교체 창 D45·D75), (3) 파트너가 텍스트 입구를 요구할 때. 어느 경우에도 우리 계정으로 외부 T2I를 대리 호출하지는 않는다.

### 6.2 크리에이터 작업 흐름

- 표준 흐름은 "이미지 모델 → I2V"다. Higgsfield 스스로 Soul Cinema를 I2V용 키프레임으로 소개하는 자료가 있다 [2차].
- 우리 자리는 그 흐름의 **카메라 단계**다. 입력: 이미지 + (선택) 텍스트. 출력: 영상, 세계 파일, ShotScript, Proof-of-Shot. 차이는 재촬영이다. 같은 세계에서 무브와 렌즈를 바꿔 다시 찍는 한계비용은 v2.1 추정으로 4K120 10초에 7–15 T4-분이다(세계 생성 비용과 분리, 실측 대상).
- 과금 단위 후보: 세계 1개 + 샷 N개. 숫자는 E0 TFU 가격표 확정 뒤 정한다.
- [신규] 세계 파일 내보내기는 기본으로 `BIO`를 뺀다. 인물 세계를 외부 도구로 내보내면 그 뒤의 사용은 사용자 책임이라고 내보내기 화면에 적는다.
