## 0. 결론 요약

1. **"라이선스는 필요 없지만 의무는 생긴다."** 사용자가 자기 이미지를 넣고 영상을 받는 추론에는 생성기 회사의 허락이 필요 없다. 확인한 주요 생성기 약관은 모두 출력 소유권을 사용자에게 두거나 주장하지 않는다(§3.1). 우리는 그 약관의 당사자도 아니다. 대신 업로드를 받는 순간 네 가지 의무가 생긴다. 권리 보증, 개인정보, AI 생성물 표시, 신고 처리다.
2. **Soul 방화벽을 사용자 콘텐츠 방화벽(ECF, External Content Firewall)으로 일반화한다.** soul 비트를 ext 비트로 넓힌다. ext=1인 모든 계산은 클린룸 레인에서 돌고, 학습·보정·전역 은행·공유 프리셋으로 흐르지 않는다. 태그는 `USER`, `USER-DERIVED`, `EXTGEN:<생성기>`(회사가 직접 받은 외부 생성기 출력, Soul 포함), `COMP`(경쟁 출력), `HOLDOUT`(벤치) 등으로 확장한다(§1).
3. **1-입력 원칙.** 이미지 한 장에 세계 W를 피팅해 그 이미지의 영상을 만드는 것은 추론이다. 파라미터는 그 입력에만 쓰고, 다른 입력으로 넘어가지 않고, 프로젝트와 함께 삭제한다. v2.1에서 회색지대(CT33)로 묶였던 "Soul 스틸 관측 피팅"이 이 원칙으로 Plan A(콘텐츠 사용) 안으로 들어온다. 법무 의견으로 확정한다(Q27).
4. **새로 드러난 제약: 개발 방화벽.** Higgsfield 5.1(iii)은 출력을 "경쟁 제품·서비스의 개발·개선"에 쓰는 것을 막는다. Google 약관은 생성물을 "ML 모델 또는 관련 AI 기술 개발"에 쓰는 것을 막는다. Midjourney는 서비스를 "경쟁 제품 개발" 목적으로 쓰는 것을 막는다. I2V 전환으로 우리는 Higgsfield가 호스팅하는 I2V와 같은 시장에 선다. 그래서 **외부 생성기 출력은 학습뿐 아니라 개발 루프(회귀셋, 튜닝, 하이퍼파라미터·체크포인트 선택)에도 넣지 않는다.** 측정은 동결 평가로만 하고, 고칠 때는 오픈 모델 프록시에서 재현한 뒤 고친다(§3.3, CT-R3).
5. **학습 원천은 셋뿐이다.** `ENGINE`(우리 엔진 트랙), `CAPTURE`(자체 촬영), `ASSET`(CC0 등 라이선스 확인 에셋). 사용자 세계는 래칫 밖이다. 플라이휠은 엔진 hero를 가짜 입력으로 쓰는 **Self-Input 래칫**으로 돈다(§1.11).
6. **학습에 쓸 수 있다고 확인된 외부 이미지 출처는 Apache-2.0 오픈 모델뿐이다.** Z-Image-Turbo와 FLUX.2 [klein] 4B다([검증], Hugging Face 메타데이터). FLUX [dev] 계열은 출력으로 경쟁 모델을 학습하는 것을 금지한다([검증], 라이선스 원문). Higgsfield, Google은 명시적으로 금지한다. OpenAI, Midjourney는 경쟁 조항이 있다. 나머지는 미확인이다(§3.1).
7. **Soul은 핵심 의존성에서 선택적 입력원·파트너로 내려간다.** MCP 자동 호출은 0이다. Soul 경유 POLISH와 X-Soul은 폐기한다. 웹 수동 생성은 90일 약 1,100회(v2.1 2,900 + MCP 1,600)다. 데모 입력, 내부 비교, 키 아트에만 쓴다(§4).
8. **승인 단계 재정의.** Plan A는 넓어진다(1-입력 추론 포함). A+는 "교차 입력 재사용과 공개"로 줄어든다. S는 보류한다. 일반화한 사다리는 U0(추론·콘텐츠) / U1(교차 입력 재사용·공개) / U2(학습)다(§4.2).
9. **Higgsfield는 보류.** 내용 거절이 아니라 접수 경로 문제다(티켓 #317768). 재접촉은 데모 릴과 같은-사진 벤치 결과가 나온 뒤 Contact Sales 폼으로 한다. 제안은 "허락"이 아니라 **비독점 유통 파트너십("세계로 열기")**이다(§4.6).
10. **T2V 입구.** 제품은 **이미지 전용**(+ 선택 텍스트)으로 연다. 엔진 교사 측량 모드 hero는 **내부 전용**으로 남긴다. 용도는 넷이다. Engine 트랙 기준선(제거 가능성 증명), 공개 벤치 입력(재배포 가능한 Apache 출력), Self-Input 래칫, 개발 프록시(§5).
11. **모델 중립은 증명 가능한 주장이어야 한다.** "어떤 이미지 모델의 출력으로도, 어떤 사용자 업로드로도 학습하지 않는다"를 감사 로그, 카나리아 결과, 투명성 보고서로 뒷받침한다. 공개 주장은 모두 주장 장부(claim → 지표 → 입력 세트 → 트랙 → 날짜)에 묶는다(§6.4).
12. **규제 일정.** 한국 AI 기본법 제31조 표시 의무(2026-01-22 시행, 과태료 계도 1년 이상) [2차], EU AI Act 제50조 투명성 의무(2026-08-02 적용, 기계판독 표시는 기존 시스템에 한해 2026-12-02까지 유예) [2차], 미국 TAKE IT DOWN Act 신고·48시간 삭제(2026-05-19부터 FTC 집행) [2차]. 대응은 C2PA 출처 표시 + Proof-of-Shot + 발명 지도 + 가시 라벨이다(§2.4).

### 1.2 계보 태그 체계 v3

v2.1의 순도 등급(D0–D3, DS)과 라벨 태그는 그대로 두고, **출처 오염(taint) 태그**를 한 축 더 둔다. 한 아티팩트는 taint 집합과 mode(none < inspired < derived < authored)를 가진다.

- **v2.1 태그와의 대응.** `SOUL` = `EXTGEN:soul`, `SOUL-DERIVED` = `EXTGEN-DERIVED:soul`, `SOUL-INSPIRED` = `EXTGEN-INSPIRED:soul`. 코드와 문서는 새 이름을 쓰고 별칭표에 옛 이름을 남긴다(CT39 원칙).
- **사용자 콘텐츠에는 INSPIRED가 생기지 않게 한다.** 엔지니어는 사용자 콘텐츠를 보지 않는다(§1.4 브레이크글라스). CI는 사람이 본 것을 감지하지 못하므로 접근 통제와 접근 로그로 막는다.
- **TEL-CAGG의 자리.** "데이터에서 파생된 데이터"를 학습에 쓰는 것도 막는 약관이 있다(Higgsfield 5.2(iv) "any data derived therefrom"). 그래서 콘텐츠 파생 집계는 사람이 읽는 보고서와 공개 KPI로만 쓰고, 생성기·선택기 조정 신호로 쓰지 않는다.

### 1.3 prov 필드, 전파 규칙, 1-입력 원칙

**STRATA 블록 필드.** v2.1의 `own`, `meta.prov`를 넓힌다.

```
meta.prov = {
  taint:  set[Tag],            # §1.2
  mode:   none|inspired|derived|authored,
  roots:  set[UploadID|AssetHash],   # 삭제 폐포 계산용
  ns:     user_vault|ext_vault|comp_vault|pub_bench|train_ok,
  src:    {gen, model, version, date, plan, account, terms_hash, c2pa_claim?}  # EXTGEN·USER(가능한 경우)
}
ext  = |taint ∩ {USER, USER-DERIVED, EXTGEN:*, EXTGEN-*}| > 0
comp = COMP ∈ taint ;  hold = HOLDOUT ∈ taint
Merkle 키 ∋ (ext, comp, hold, ns)     # v2.1의 soul 비트 자리
```

**전파 규칙 (의사코드).**

```
def derive(op, parents, human_only=False):
    x.taint = ⋃ p.taint for p in parents
    x.roots = ⋃ p.roots for p in parents
    x.mode  = 'inspired' if human_only and any(p.ext for p in parents) else max(p.mode for p in parents)
    x.ns    = most_restrictive(p.ns for p in parents)   # user_vault > ext_vault > comp_vault > pub_bench > train_ok
    return x

BLOCK_TRAIN = {USER, USER-DERIVED, EXTGEN:*, EXTGEN-DERIVED:*, COMP, HOLDOUT, D3, NC}
BLOCK_DEV   = {USER, USER-DERIVED, EXTGEN:*, EXTGEN-DERIVED:*, COMP}

def train_ok(x, branch='main'):
    if branch == 'main':
        return not (x.taint & BLOCK_TRAIN) and not (x.mode == 'inspired' and has_ext_ancestor(x))   # Q17
    if branch == 'optin-v1':                                  # 장기
        return x.taint <= {CAPTURE, ENGINE, ASSET, HUMAN, OPTIN} and optin_valid(x.roots)

def dev_ok(x):         # 회귀셋, 튜닝, HP·체크포인트·프리셋 선택, 자동 2AFC 보상
    return not (x.taint & BLOCK_DEV)

def eval_report_ok(x): # R-EVAL: 별도 프로세스, 결과는 사람이 읽는 보고서와 공개 KPI뿐
    return True

def delete_project(P):
    destroy(K[P])                                   # ≤24h, 백업까지 읽을 수 없게 됨
    gc({y : y.roots ∩ uploads(P) ≠ ∅})              # ≤7d, 주 저장소와 캐시
```

**1-입력 원칙 [운용].** 다음 네 조건을 모두 지키는 최적화는 "모델 학습"이 아니라 그 입력에 대한 추론(테스트타임 최적화)으로 본다. 이 해석이 CT-R2이고, 법무 의견으로 확정한다(Q27).

| # | 조건 | 강제 수단 |
|---|---|---|
| 1 | 최적화되는 파라미터는 그 입력의 장면 표현(W, θ_in, 조명, 견본)뿐이다. 공유 가중치(G-Adapter, MRH, TexelFM 등)에는 그래디언트가 0이다 | 클린룸 레인에서 공유 가중치는 읽기 전용으로 마운트 |
| 2 | 결과는 그 입력의 요청자에게만 쓰인다. 다른 프로젝트·사용자로 넘어가지 않는다 | ns = user_vault, 프로젝트 키 암호화 |
| 3 | 어떤 학습·개발·전역 은행으로도 흐르지 않는다 | Lineage CI(§1.5), 카나리아(§1.6) |
| 4 | 프로젝트 삭제 때 함께 삭제된다 | crypto-shredding, 삭제 카나리아 |

- **회사 데모에도 같은 원칙이 적용된다.** 창업자가 Soul 스틸로 데모 세계를 짓는 것은 조건 1–3을 지키는 한 U0다. 조건 4 대신 ext_vault에 보존한다(회사 콘텐츠이므로).
- **교차 입력 재사용은 U1이다.** 예: Soul 입력에서 자동 추출한 θ를 공유 프리셋 라이브러리에 넣어 다른 세계에 쓰는 것. 이것은 모델 학습은 아니지만 "데이터를 다른 입력으로 옮기는" 행위라 약관 해석 대상으로 남긴다.

### 1.6 카나리아 5종

| 카나리아 | 방법 | 주기 | 정상 | 지표 |
|---|---|---|---|---|
| C1 태그 | 가짜 `USER` 태그 샘플을 빌더 9곳(학습 샤드, 래칫 샘플러, Texel/Swatch 색인, 프리셋, TRT 보정, VAE 쌍, 링버퍼, 2AFC 쌍, 회귀셋)에 주입 | 주 1회 | 9곳 모두 실패 | 통과 9/9 |
| C2 픽셀(기억 탐지) [조합] | 비밀 seed로 만든 64×64 고유 패턴 16종을 **엔진이 그린 가짜 업로드**(권리 문제 없음)에 심어 운영 경로로 보낸다. 다음 학습 세대 뒤, 후보 2¹⁶개 중 카나리아 패턴의 TexelFM 재현 순위를 잰다 | 학습 세대마다 | 노출도 < 10 bit | exposure = log₂ N − log₂ rank (비밀 공유자 노출도 [부품]). 무작위 기대치 약 1.4 bit. 10 bit면 카나리아 하나의 우연 확률 약 0.1%, 16개 중 하나라도 걸릴 우연 확률 약 1.6% |
| C3 삭제 | 업로드 → 렌더 → 삭제 요청 | 주 1회 | 24 h 안에 K_P 없음, 7일 안에 모든 저장소에서 root-id와 내용 해시 0건 | 삭제 SLA 충족률 100% |
| C4 송신 | 클린룸 레인에서 허용 목록 밖 호스트로 송신 시도 | 주 1회 | 차단 | 차단률 100% |
| C5 개발 방화벽 | `EXTGEN:test` 태그 이미지를 회귀셋 빌더, HP 탐색기, 체크포인트 선택기에 주입 | 주 1회 | 3곳 모두 실패 | 3/3 |

- C2는 태그가 지워져도 누수를 잡는다. 수십M 모델이라 기억 위험은 작을 것으로 보지만(추정), 사용자에게 "학습하지 않는다"를 말하려면 태그 검사만으로는 부족하다.
- 결과는 분기별 투명성 보고서에 싣는다(§6.1).

### 1.10 옵트인 학습을 한다면: 조건 [`장기`]

창업자 규칙은 "출처 생성기 약관 확인 불가 시 금지"다. 업로드 이미지가 어느 생성기에서 왔는지는 확인할 수 없다(C2PA는 지워지거나 위조된다. Higgsfield 한 곳만 해도 50개 넘는 모델을 호스팅한다 [2차]). 그래서 AI 생성 이미지는 사실상 대상이 아니다.

| # | 조건 | 판정 |
|---|---|---|
| 1 | **대상은 사용자가 직접 촬영한 실사 사진(CAPTURE-USER)만.** 사용자가 "AI 생성·AI 편집 아님"을 진술 | 필수 |
| 2 | 진술과 증거가 맞을 것: 카메라 EXIF 일관성, C2PA에 AI 생성 주장 없음, (선택) RAW | 불일치면 제외 |
| 3 | 인물이 탐지되면 제외(동의서 업로드 기능 전까지). 미성년자 의심이면 무조건 제외 | 필수 |
| 4 | 위치·기기 정보 제거 | 필수 |
| 5 | 약관과 분리된 별도 동의, 항목·목적·보유기간 명시, 언제든 철회 | 필수(개인정보보호법상 별도 동의 원칙) |
| 6 | **철회 시 기여 제거:** 해당 루트가 든 샤드를 빼고 영향받는 모델만 다음 정기 재학습(≤30일)에서 다시 학습한다. 수십M 모델이라 가능하다. 예: TexelFM-35 한 세대 약 90 T4-h(v2.1 §5.6) | 필수. 약관에 "이미 배포된 모델은 다음 재학습까지 남는다"를 적는다 |

- **판정: P1·P2에서는 옵트인 학습을 열지 않는다.** 래칫은 Self-Input으로 충분히 돌아야 한다(§1.11). 옵트인은 실사 시장(§6.3)의 분포 차이가 측정으로 확인될 때 연다.

### 1.11 래칫 영향과 Self-Input 래칫 [조합]

- **문제.** I2V에서 운영 트래픽은 전부 ext=1이다. v2.1 플라이휠(관할 이양 래칫)은 사용자 데이터를 한 바이트도 먹지 못한다. 경쟁사는 사용자 업로드로 학습하는 경우가 많다(Higgsfield 4.4, BFL API 약관 [검증·2차]). 우리는 그 길을 스스로 닫는다.
- **해법: Self-Input 래칫.** 엔진이 사용자 입력과 같은 모양의 가짜 입력을 만들고, 그 입력으로 사용자와 똑같은 I2V 경로를 돈다. 결과 세계는 `SI` 태그로 래칫에 들어간다.

```
SelfInput(prompt p, style s):
  x_in ← EngineHero(p, survey=False, look=s)        # Z-Image(Apache) 또는 klein 4B(Apache), 시네마 프롬프트 + 룩 θ로 렌더 후 운송
       | CaptureOwn(scene)                          # 자체 촬영 실사
  x_in ← Perturb(x_in; escher_defect ~ q, grain, grade, crop)   # 에셔 결함·필름 질감 주입으로 'AI 이미지 같은 입력' 흉내
  W    ← I2W(x_in)                                   # 사용자 경로와 같은 코드, 단 ns = train_ok
  Ratchet.add(W, tag=SI)                             # ext = 0
```

- **분포 맞추기.** 가짜 입력 분포를 실제 입력 분포에 맞추는 신호는 `TEL-SYS`(무브 등급 비율, 실패 코드)와 사람이 읽는 `TEL-CAGG` 보고서뿐이다. 자동 조정 신호로 쓰지 않는다(§1.2).
- **물량.** v2.1 라이브러리 목표(D90 ≥300 세계)를 그대로 쓰되, 그중 SI 비율을 50% 이상으로 둔다(추정). 세계당 비용은 v2.1 라이브러리 세계와 같다(G3 계획 1.8 T4-h).
- **정직한 한계.** SI 입력은 Soul·GPT Image 같은 실제 AI 이미지의 "개념 기획"을 흉내 내지 못한다(A/B에서 Z가 진 축). 그래서 개념 축의 분포 차이는 남는다(R44). 대응은 동결 측정(INT 세트)으로 차이를 재고, 차이가 크면 파트너 계약 U2(§4.2)로 연다.

### 3.3 개발 방화벽과 프록시 재현 규칙 [신규 운용, CT-R3]

- **문제.** 학습 금지만으로는 부족하다. Higgsfield 5.1(iii)과 Google 소비자 약관은 "개발·개선"에 출력을 쓰는 것 자체를 막는다. 엔지니어가 Soul 입력에서 깨진 사례를 보고 코드를 고치고, 그 이미지를 회귀셋에 넣고, 그 이미지로 하이퍼파라미터를 고르면 "출력으로 경쟁 서비스를 개선"한 것으로 읽힐 수 있다.
- **구분.** *콘텐츠 제작 조작*(그 데모 세계의 W·샷·조명·θ 파라미터, 사람 연출)은 콘텐츠 사용이다. *시스템 변경*(코드, 가중치, 하이퍼파라미터, 회귀셋, 프리셋 라이브러리)은 개발이다.
- **규칙.**
  1. EXTGEN·USER·COMP 항목은 회귀셋, HP 탐색, 체크포인트·프리셋 선택, 자동 2AFC 보상에 들어가지 않는다(CI 규칙 8, 카나리아 C5).
  2. 측정은 **동결 평가**로만 한다. 코드가 동결된 버전으로 한 번 돌리고, 결과는 사람이 읽는 보고서(R-EVAL)로만 남긴다.
  3. **프록시 재현.** EXTGEN 입력에서 발견한 결함을 고치는 변경은, 같은 결함을 ENGINE·SI·CAPTURE·PUB 입력에서 재현한 사례를 PR에 붙여야 병합된다. 재현 못 하면 고치지 않는다.
  4. 프록시 생성기: Z-Image 또는 klein 4B에 "Soul풍" 시네마 프롬프트와 θ_look을 준 출력(v2.1 E3 (c) Soul풍 대리 판독의 일반화), 그리고 §1.11의 에셔 결함 주입.
- **비용.** 프록시 재현 1건에 엔지니어 시간 0.5–2 h(추정). 프록시 세트 생성은 SI 공장과 같다.
- **완화 조건.** 법무 의견이 "개발"을 좁게 해석하면(예: 비학습 테스트는 개발이 아니다) 규칙 2–3을 완화한다. 1은 유지한다.

- 생성기 7곳(Higgsfield, OpenAI, Midjourney, Google 소비자, Gemini API, BFL, Adobe)과 경쟁 비디오 API 4곳, 합계 11곳의 약관 전문을 매월 1일 해시로 보관한다(v2.1 §11.6 약관 스냅샷의 확장).

## 4. Soul의 v3 역할과 Higgsfield 부록 v3

### 4.1 역할 변화

창업자 결정은 "Soul은 버리지 않는다"(v2.1)와 "Soul 없이도 된다"(I2V)를 함께 성립시킨다. Soul은 **핵심 의존성이 아니라 가장 좋은 입력원 가운데 하나**가 된다. I2V에서 개념과 룩은 입력 이미지가 소유한다. 그 입력이 Soul이면 Soul의 미감이 첫 프레임을 소유하고, 우리는 그 미감을 무너뜨리지 않고 카메라를 움직인다.

### 4.2 승인 사다리 재정의: A / A+ / S → U0 / U1 / U2

외부 생성기 모두에 쓰는 일반 사다리로 바꾼다. Soul의 v2.1 단계는 아래처럼 대응한다.

| 단계 | 일반 정의 | Soul의 예 | 필요한 것 | v2.1 대응 |
|---|---|---|---|---|
| **U0 콘텐츠·추론** | 출력을 콘텐츠로 쓰고, 1-입력 원칙으로 세계를 피팅해 그 이미지의 영상을 만든다. 동결 측정 결과를 사람 보고서로 남긴다 | 데모 입력, 키 아트, 세계 속 이미지, INT-soul 동결 측정 | 약관 안이라는 우리 해석 + 법무 의견(Q27). Higgsfield 확인은 있으면 좋지만 전제가 아니다 | Plan A + A+의 단일 장면 피팅 |
| **U1 교차 입력 재사용·공개** | 한 출력에서 뽑은 파라미터를 다른 세계에 재사용, 생성기 이름을 건 비교 결과 공개, 파생 프리셋 공개 | θ 자동 추출 프리셋 공유, "Soul 입력 대결" 공개, v2.1 Hybrid-A 프리셋 공개(Q13) | 서면 확인 또는 파트너 계약 | A+ 일부, Q13 |
| **U2 학습** | 출력이나 파생 데이터로 모델 학습 | v2.1 S1(CamFM-CRM 12M, LookPrior-S 2M, MRH-Aes ≤2M), S2(CamFM-Intent 20M, MassingFM 24M) | 서면 승인(5.2(iv) 예외) | Plan S |

- **S의 가치는 내려갔다.** I2V에서 첫 프레임 구도는 입력이 소유한다. CamFM-CRM이 Soul에서 배울 구도 취향은 카메라 무브 중 프레이밍에만 남는다. LookPrior-S는 T2V 입구가 사라져 필요 없다(I2V 결정 §2.2). 그래서 S는 파트너십 협상의 선택 의제로만 둔다.

| PUB 입력의 AI 이미지 몫 | 재배포 가능한 AI 이미지 입력은 Apache 출력뿐이다 | PUB의 약 1/3 |
| Self-Input 래칫 | 사용자 세계는 래칫 밖이다(§1.11) | D90까지 SI ≥150 세계 |
| 개발 프록시 | 개발 방화벽의 재현 사례(§3.3) | 결함당 1–4장 |
| 내부 라이브러리 | 세계 속 이미지, 원경, 데모 배경 | 필요 시 |

- 내부 용도의 품질 기준은 "최고의 첫 프레임"이 아니라 "사용자 입력 같은 첫 프레임"이다. 그래서 오디션을 64→16→4(112 TFU)에서 16→4로 줄인다. 약 28 TFU, 세계당 교사 호출의 약 4%다(112 × 16/64로 비례 계산, 추정).
- 레벨 2(그림체) 입력의 프록시는 klein 4B(Apache, 멀티 레퍼런스 편집)로 만든다. 출력 제한이 없어 SI와 PUB에 쓸 수 있다.

### 5.3 추천과 근거, 뒤집힐 조건

**추천: O1(이미지 전용)을 P1 제품 입구로, O2는 파트너 계약 형태로 `P1-확장`, 엔진 hero는 내부 전용(O3 비노출).**

| 근거 | 내용 |
|---|---|
| 미감 | 첫 프레임은 사용자가 가장 먼저 판단하는 것이다. 엔진 hero는 50축 중 1승이다. 이미지 모델 경쟁에 참전하지 않으면 그 1승을 보여 줄 일도 없다 |
| 권리 | 우리가 이미지를 생성하지 않으면 생성 프롬프트 심사와 이미지 생성물 표시 범위가 줄어든다. 남는 것은 업로드 심사와 영상 표시다 |
| 중립 | 우리 T2I가 없어야 "이미지 모델 전쟁의 스위스"가 말이 된다 |
| 컴퓨트 | hero 오디션 112 TFU 절감(16%) |
| 벤치 | 같은 첫 프레임 대결(T2)이 공정하다. T2V 비교가 필요하면 "T2V-합성(사용한 T2I 이름)" 트랙으로 표기한다 |

**뒤집힐 조건.** (1) TEL-SYS 퍼널에서 "이미지 없음"으로 이탈하는 비율이 높고 파트너 통합이 늦을 때(임계값은 창업자가 정한다), (2) Apache 오픈 이미지 모델이 개념 축까지 이길 때(측량 교사 재오디션에서 확인), (3) 파트너가 텍스트 입구를 요구할 때. 어느 경우에도 우리 계정으로 외부 T2I를 대리 호출하지는 않는다.

## 6. 사업 포지셔닝 (검증 가능한 주장만)

### 6.1 모델 중립: 이미지 모델 전쟁의 스위스

| 주장 | 검증 방법 | 상태 |
|---|---|---|
| 어떤 이미지 모델의 출력도 입력으로 받는다 | 지원 형식 공개, PUB·INT 세트의 생성기 분포 공개 | 설계 |
| 어떤 생성기의 출력으로도, 어떤 사용자 업로드로도 학습하지 않는다 | Lineage CI 로그, 카나리아 C1–C5 결과, 분기 투명성 보고서 | 설계(D30 v0) |
| 이미지 모델이 좋아지면 우리 결과도 좋아진다 | 같은 PUB 장면을 두 세대 이미지 모델 입력으로 돌린 2AFC(첫 프레임 미감 몫) | 가설. 측정 전 주장 금지 |
| 같은 세계에서 여러 샷을 결정론적으로 다시 찍는다 | Proof-of-Shot 공개, 왕복 비트 동일 | v2.1 설계, D14 왕복 v0 |
| 발명 비율을 공개한다 | 출력마다 발명 지도 사이드카 | 설계 |

- 중립은 이미지 모델 회사에도 의미가 있다. 우리가 그들의 출력을 증류하지 않는다는 것을 감사 가능하게 보여 주면, 유통 파트너십(§4.6)의 상대가 될 수 있다.

### 6.2 크리에이터 작업 흐름

- 표준 흐름은 "이미지 모델 → I2V"다. Higgsfield 스스로 Soul Cinema를 I2V용 키프레임으로 소개하는 자료가 있다 [2차].
- 우리 자리는 그 흐름의 **카메라 단계**다. 입력: 이미지 + (선택) 텍스트. 출력: 영상, 세계 파일, ShotScript, Proof-of-Shot. 차이는 재촬영이다. 같은 세계에서 무브와 렌즈를 바꿔 다시 찍는 한계비용은 v2.1 추정으로 4K120 10초에 7–15 T4-분이다(세계 생성 비용과 분리, 실측 대상).
- 과금 단위 후보: 세계 1개 + 샷 N개. 숫자는 E0 TFU 가격표 확정 뒤 정한다.

### 6.3 실사 사진 시장: 조건부

| 시장 | 쓰임 | 권리·규제 조건 | 배치 |
